## 1. Goal

On first launch the app asks for a provider and key, stores the key in the OS keychain, lists the provider's models for the user to pick, and chats through OpenAI-compatible or Anthropic providers. A Models page tests, re-keys and deletes connections. M1's `config.local.json` path is deleted. This was the human's request on 2026-10-29, and it is what the design's "Flow: add a cloud model" describes.

Done means (design doc, "Milestones"):

- [ ] Add, test, and delete cloud connections from the Models page
- [ ] Keys saved in Windows Credential Manager, never in SQLite
- [ ] Anthropic adapter streams replies
- [ ] Every error kind shows a clear message in the UI

## 2. Decisions made while planning

- **Keychain behind a trait.** `SecretStore` with `Keychain` (keyring 4.2, real) and `MemoryStore` (tests). Tests never touch the real Credential Manager. keyring 4's default feature picks the OS store per target, so no platform features are needed (the 3.x note in `known-issues.md` is outdated).
- **Connection rows in SQLite, keys in the keychain.** Entry service `com.aidp.desktop`, user `connection-{id}`. SQLite keeps the last 4 characters of the key, and only when the key has at least 12 characters.
- **`u32` ids and timestamps**, because specta rejects 64-bit integers.
- **Database** `{app_data_dir}/aidp.db` with `connections` and `models` only; migrations via `PRAGMA user_version`, no extra crate. Capability columns and the history tables come in later migrations.
- **A failed test saves nothing.** `add_connection` lists the provider's models first, then writes the row, then the keychain entry, and rolls the row back if the keychain fails.
- **Anthropic over raw HTTP** (Rust has no official SDK): `anthropic-version: 2026-10-21`, `max_tokens` 8192, system messages moved to the top-level `system` field, `refusal` stop reason handled.
- **Shared gateway code.** The status mapping and the SSE read loop move from the OpenAI-compatible adapter into `gateway/http.rs`, so both adapters share them. M1's nine fake-server tests are the safety net for that refactor.
- **One shared `reqwest::Client`** (the M1 carry-over), with a 15 s timeout on list and test requests.
- **`remark-gfm` for tables** is included as Task 8 step 6 (decision D1, default yes), the other M1 carry-over.
- **The Models page is the connection settings surface**; M5's Settings links to it. The human asked for "view and modify in settings"; modifying means replacing the key, and the full key is never shown (security rule 2).
- **Tasks 6 to 8 share one commit**, because removing `chat_config` and changing `sendMessage` breaks the frontend typecheck until the UI is rewritten, and a red tree must not be committed.

## 3. Built, changes from the plan, what's left

### Changes from the plan (Tasks 1 to 5)

- **Test placement:** `map_error_type_table` and `factory_builds_the_right_adapter` live in `tests/anthropic.rs`, not as unit tests in `anthropic.rs` and `gateway/mod.rs`. Same checks.
- **`SecretString` has no `PartialEq`**, so tests compare `expose_secret()` or the error variant (`unwrap_err() == SecretError::NotFound`).
- **Review fixes (2026-10-30, Claude Code):**
  - The Anthropic `x-api-key` header is marked sensitive, as the plan required.
  - A closed chat channel stops an Anthropic stream with `Cancelled`, as in M1.
  - Stop works while an Anthropic error body is being read.
  - Anthropic stream data that is not JSON is an error; valid JSON of an unknown shape is still skipped.
  - Keys are trimmed before they are tested and saved. This was a plan gap: a key pasted with a trailing newline failed as an invalid key.
  - New tests: `malformed_event_is_an_error`, `closed_channel_stops_the_stream`, `keys_are_trimmed_before_saving`.

### Changes from the plan (Tasks 6 to 8)

- **`ChooseModels` initial selection:** Added `initialSelected?: string[]` prop to `ChooseModelsProps`, defaulting to empty set so that in `AddConnectionDialog` models are not pre-selected by default and ticking one model saves only that model.
- **JSDOM test setup:** Added explicit `cleanup()` in `afterEach` for `ModelsScreen.test.tsx`, `AddConnectionDialog.test.tsx`, and `ChatScreen.test.tsx` because vitest runs without global jest hooks. Defensive optional chaining used on `scrollIntoView` which JSDOM does not implement.
