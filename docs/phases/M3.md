## 1. Goal

A Workspace screen: open a folder, browse a `.gitignore`-aware file tree, edit files in CodeMirror 6 tabs, ask a model about the open file or selection in an AI panel, and apply a code block from the reply through a diff that reaches the disk only on Accept. No tool calling yet, so M3 works with every model (design doc, "Coding workspace").

## 2. Decisions made while planning

The full list is in the plan, under "Decided in this plan". The ones that shape the code most:

- **Workspace-relative paths only**, resolved in Rust by pushing components onto the canonical root (never joining the string, because `\\?\` verbatim paths on Windows do not treat `/` as a separator), then checked with `starts_with`. `..`, absolute paths, drive prefixes and `:` are refused outright.
- **Folder picker opened from Rust** (D1), so the UI never hands an absolute path to the OS. `open_recent` accepts only paths from the stored recent list (D2).
- **Line endings, BOM and a version token round-trip** through `read_file` and `write_file`; a stale version gives `ChangedOnDisk`.
- **Separate chat surfaces** (`chat`, `workspace`), so the AI panel and Chat stream at the same time.
- **Apply needs a saved file** (D3); Reject never writes; Accept writes exactly the text shown in the diff, after a one-time confirmation in folders without git.
- **Unsaved work is never dropped silently**, including when the window closes.

## 3. Built, changes from the plan, RAM budget, what's left

### What was built

- **Workspace core in Rust** (`src-tauri/src/workspace/`):
  - `resolve`: relative paths only, components pushed onto the canonical root, then canonicalize and `starts_with`. `..`, absolute paths, drive prefixes, UNC paths and `:` are refused.
  - Secret-file filter, applied to both the requested name and a link's target.
  - `list_dir` with the `ignore` crate: `.gitignore` applies inside git repositories, dotfiles are shown, `.git` is hidden.
  - Text read and write: 2 MB and UTF-8 limits, line endings and BOM preserved, a version token that catches `ChangedOnDisk`.
  - Also `is_git` and `display_path`.
- **Workspace commands:**
  - `open_folder`, using the dialog plugin called from Rust only.
  - `recent_folders` and `open_recent`, which accepts only stored paths.
  - `close_folder`.
  - `list_dir`, `read_file` and `write_file`, run in `spawn_blocking`.
  - The `settings` table (migration 2) holds the recent folders.
- **Chat surfaces** (`chat`, `workspace`) so the two can stream at once; `MessageList`, `Composer` and `ModelPicker` shared by Chat and the workspace; Apply on code blocks.
- **Workspace screen:**
  - A lazy, virtualized tree.
  - CodeMirror 6 tabs: languages load on demand, one-dark theme, unsaved-change dots, Ctrl+S, and a conflict bar with Overwrite and Reload.
  - An AI panel with file and selection chips. Secret files start without the file chip, and files over 100,000 characters can only send a selection.
  - Apply → unified diff → Accept or Reject.
  - A no-git banner, plus a one-time confirmation before the first Accept.
  - Unsaved-change prompts for closing a tab, switching folders and quitting (`CloseGuard`).
- **M2 follow-ups:** Choose models keeps the current picks; delete, model-list, save and load errors are shown.

### Changes from the plan

- **Release CSP allows inline styles** (decision 0009). The plan assumed CodeMirror would use constructable stylesheets. It only does that inside shadow roots: on a normal page it adds a `<style>` tag, which the strict policy blocked. The live check found an unstyled editor in the release build. The human chose `style-src 'self' 'unsafe-inline'` over a nonce.
- **Review fixes:** three review passes, all committed with tests.
  - **Tasks 1 to 4:**
    - `open_recent` became async, and recents became best-effort.
    - A broken (poisoned) lock is handled.
    - `display_path` handles network folders.
    - The secret check also looks at a link's target.
  - **Tasks 5 to 11:**
    - Typed edits never reached the buffers, so Save wrote the original text. Editor states now write themselves back.
    - Save refuses to write without a buffer.
    - Tabs use the requested path.
    - Save all stops if any file failed.
    - Opening another folder clears the old buffers.
    - Edits typed during a save stay unsaved.
    - A selection can be sent without the file chip.
    - The close guard needs a listening window before it blocks.
- **The close-guard commands live in `src-tauri/src/close_guard.rs`**, as the plan's file table had it, not in `commands/`.
- **Dependency reasons missing from commit bodies.** Commits 405533c, d3d3419, 9f2b299, eb84ea4 and fb38c85 added dependencies with no reason in the message (AGENTS.md section 7). The reasons, from the plan:
  - `ignore`: `.gitignore`-aware listing.
  - `tauri-plugin-dialog`: native folder picker called from Rust (decision 0008).
  - `@tanstack/react-virtual`: the virtualized tree.
  - `codemirror` with `@codemirror/state`, `view` and `language`: the editor; the last three are imported directly.
  - `@codemirror/language-data`: languages load on demand.
  - `@codemirror/theme-one-dark`: matches the chat code blocks.
  - `@codemirror/merge`: the diff view.

### RAM and workspace budget (release build, Windows 11, 2026-10-30)

Method: `docs/dev/measure-ram.md`, summed over `aidp.exe` and its WebView2 child processes (7 processes). The budget uses Task Manager's "Memory" column (private working set). The other columns are recorded for comparison.

| | Task Manager memory | Private bytes | Working set |
| --- | --- | --- | --- |
| Idle: Chat screen, no folder | **127 MB** | 186 MB | 428 MB |
| Workspace: this repo (510 tracked files), 3 files in tabs, 1 AI reply | **155 MB** | 214 MB | 475 MB |

- **Workspace budget: 200 MB** of Task Manager memory: 155 MB plus about 25%, approved by the human. The idle target (under 150 MB) is met at 127 MB.
- The Rust process is about 6 MB; the rest is WebView2.
- The plan asked for a 1,000 to 5,000-file repo. The human chose this one; the tree loads one folder at a time, so the file count barely changes memory.
- A local model runs in Ollama's processes and is not part of these numbers (see "What's left").
