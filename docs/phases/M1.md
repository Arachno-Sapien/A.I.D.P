# Milestone M1: Chat with one cloud model

Milestone status: **Done** (closed 2026-10-29).

## 1. Goal

Type a message and get a streamed reply from one OpenAI-compatible provider, with Stop, Markdown, and code blocks you can copy. This is the model layer that the coding workspace (M3) and agent tools (M4) build on.

Done means (design doc, "Milestones"):

- [x] Type a message and get a streamed reply from one OpenAI-compatible provider. *Confirmed by the human on 2026-10-29 with a real OpenRouter model, in the dev app and in the release build.*
- [x] Stop cancels a reply midway. *Confirmed live: "Stopped" appears, the partial text stays, and the next message gets a normal reply. Tests: `stop_cancels_a_waiting_request`, `begin_cancels_previous_reply`.*
- [x] Code blocks render with a copy button. *Confirmed live in the release build: Copy pastes the exact code. Test: `Markdown.test.tsx`.*
- [x] Adapter tests cover success, 401, 429, and a dropped stream. *Nine fake-server tests in `src-tauri/tests/openai_compat.rs`, all passing.*

## 2. Decisions made while planning

- **reqwest uses `native-tls`** (Windows SChannel) instead of 0.13's default rustls with aws-lc-rs, which needs CMake and NASM on Windows. Decision record 0006 is written in Task 2.
- **The `ModelProvider` trait has only `stream_chat` in M1.** `list_models` and `test_connection` arrive in M2 with the Models page that uses them.
- **The adapter sends only `Delta`.** The `send_message` command sends the single `Done` or `Error`.
- **The design's catch-all `ProviderError` kind is the `Provider` variant,** to avoid `ProviderError::ProviderError`.
- **No `stream_options` in requests.** Usage is reported only when the provider sends it.
- **The M1 key file is `config.local.json` in the app config folder,** outside the repo. M2 replaces it with the keychain.
- **A small in-app navigation guard** keeps the window on the app when a reply contains a link (security rule 5).
- **M1 chats live in memory only.** Long-list virtualization comes with history in M5.

## 3. Built, changes from the plan, what's left

### What was built

1. **Gateway and Trait (`src-tauri/src/gateway/`):**
   - Core types: `Role`, `ChatMessage`, `ChatRequest`, `Usage`, `ProviderError`, `ChatEvent`.
   - `ModelProvider` trait with `stream_chat`.
   - `SseLines` byte parser with line buffer handling arbitrary network chunks and multi-byte UTF-8 boundaries.
2. **OpenAI-Compatible Adapter (`src-tauri/src/gateway/openai_compat.rs`):**
   - Streaming SSE reader sending `Delta` events over a Tauri `Channel`.
   - Error mapping for HTTP 401/403 (`InvalidKey`), 429 (`RateLimited`), 404 (`ModelNotFound`), 400 (`ContextTooLong`), connection drop / premature close (`Provider`), and network failure (`Offline`).
   - Clean request and stream cancellation via `tokio_util::sync::CancellationToken`.
   - Decision record 0006 (`docs/decisions/0006-reqwest-native-tls.md`).
   - 8 wiremock integration tests in `src-tauri/tests/openai_compat.rs`.
3. **Local Config Loader (`src-tauri/src/config.rs`):**
   - Reads `%APPDATA%\com.aidp.desktop\config.local.json`.
   - Enforces HTTPS for remote cloud providers, while permitting HTTP only for localhost, loopback, or private RFC1918 IPv4/IPv6 networks.
   - API keys stored in `secrecy::SecretString` with `[REDACTED]` Debug representation.
4. **Commands and Navigation Guard (`src-tauri/src/commands/chat.rs`, `src-tauri/src/lib.rs`):**
   - `ChatState` with mutex-protected cancellation tokens.
   - `chat_config`, `send_message`, and `stop_reply` commands with typed Specta TypeScript export.
   - In-app navigation guard plugin ensuring no external URL navigation inside the app window.
5. **Frontend State and Markdown Rendering (`src/features/chat/`):**
   - Zustand store (`store.ts`) with optimistic message dispatch, history management, and streaming updates.
   - Normalized user-facing error text mapping (`errorText.ts`).
   - `Markdown.tsx` utilizing `react-markdown` with `skipHtml` (raw HTML suppression), Prism syntax highlighting (`oneDark`), and copyable code blocks with visual feedback.
   - `ChatScreen.tsx` full UI with auto-scrolling message view, streaming caret, configuration error banners, and composer.

### Changes from the plan

- In `ProviderError::RateLimited`, `retry_after_secs` was changed from `Option<u64>` to `Option<u32>`. `tauri-specta` forbids BigInt types by default to avoid JavaScript number precision loss, so `u32` cleanly maps to `number | null` in TypeScript without requiring bigint serialization workarounds.

### Fixes from the review (Claude Code, 2026-10-29)

- **Empty replies left out of the history.** A reply stopped before its first token was sent back to the provider as an empty assistant message, which some providers reject with a 400. Test: "leaves empty replies out of the history".
- **Errors inside a 200 stream are reported.** OpenRouter and others send `{"error": ...}` mid-stream. It was ignored, and the cut-off reply came back as a success. It now becomes `Provider { message }`. Test: `provider_error_inside_stream_is_reported`.
- **Stop can't be lost.** `send_message` now registers the reply with `ChatState::begin()` before loading the config, so a Stop pressed in that gap still cancels it.
- **IPv6 local addresses are recognised.** `host_str()` keeps the brackets (`[::1]`), so the IPv6 loopback and unique-local check could never match. Test: `ipv6_local_hosts_are_local_http`.
- **Box 1 to 3 unticked.** They had been ticked before the human's live check.
- **Markdown styling.** Tailwind's reset left headings, lists and paragraphs unstyled inside replies. `Markdown.tsx` now wraps replies in `reply-md`, styled in `src/App.css` with Tailwind utilities (no new dependency). Test: "renders headings and lists inside the reply wrapper". Not covered: tables, strikethrough and task lists, which need `remark-gfm` (a new dependency, so a decision first).
- **Byte-order mark tolerance.** `config::load` strips a leading BOM before parsing, so `config.local.json` loads however the editor saved it. Test: `loads_a_file_saved_with_a_byte_order_mark`.

### Live check evidence

The human ran the live check on 2026-10-29 with a real provider (OpenRouter, `nvidia/nemotron-3.5-lightning:free`):
- a streamed reply with a highlighted code block;
- Stop partway through, with the partial text kept and a normal reply to the next message;
- a link that stays put when clicked;
- a wrong key ("The provider rejected the API key");
- offline ("Can't reach the provider").

After the review fixes, a fresh release build was checked once more: streaming, Copy pasting the exact code, and styled headings and lists.

Automated: Rust 18 unit tests and 9 fake-server tests, Vitest 20 tests, clippy and typecheck clean, `bindings.ts` unchanged. The AGENTS.md section 9 checklist was run over the whole M1 diff: the key appears only in the auth header, nothing logs it, no capability, security policy or `build.rs` change, no tracked config file, and nothing key-like in the git history.

### What's left (carried into M2)

- Replace `config.rs`, `config.local.json` and the "Configuration Required" panel with the keychain and a first-run "Add a model" flow. The app should ask for the provider details itself on first launch (the human's request, 2026-10-29).
- Keep one `reqwest::Client` in app state instead of building one per message, so connections are reused.
- Tables, strikethrough and task lists show as plain text. They need `remark-gfm`, a new dependency, so decide it during M2 planning.
- The header reads the model name once at startup. M2's model picker replaces it.
- No clipboard plugin is needed: `navigator.clipboard` works in the release WebView2, so the plan's possible decision 0007 does not arise.
- Milestone M2: Migrate API key storage from local config file to OS Keychain (Windows Credential Manager / macOS Keychain / Linux Secret Service), add Anthropic adapter, and implement connection management screen.
