## 1. Goal

Local Ollama models work like cloud models in Chat and the workspace: the app detects Ollama, starts it, downloads, deletes and unloads models. Chats and each folder's AI panel conversation survive a restart, and every reply records its model. A Settings screen sets the default model, the theme, and how long local models stay loaded (design doc, "Local models (Ollama)", "Data model", "Screens and user flows").

Done means (design doc, "Milestones"):

- [x] App detects Ollama and starts it if stopped
- [x] Downloaded models appear in the picker and work in Chat and the workspace
- [x] Download with progress and cancel; delete with confirmation; Free memory unloads the model
- [x] Chats survive an app restart, and each message records its model
- [x] Settings for default model, theme, and keep\_alive work

## 2. Decisions made while planning

The full list is in the plan, under "Decided in this plan". The ones that shape the code most:

- **Ollama is one built-in connection** (kind `ollama`, fixed `http://127.0.0.1:11434`, no key). Its downloaded models are synced into `models`, so the picker, the default model and each message's model work the same for every provider.
- **A new `ollama_chat.rs` adapter** uses `/api/chat` with tools, `num_ctx` and `keep_alive`, behind the same trait.
- **History:** two tables (`conversations`, `messages`); the UI decides when to save and only Rust writes SQLite. Each reply stores its model reference and name.
- **Small context windows:** what the panel attaches and what one tool result returns are capped at 2 characters per context token.
- **The theme** swaps Tailwind's neutral palette through CSS variables.
- **Found while planning:** the model picker splits its key on every `:`, which breaks Ollama names like `qwen2.5-coder:1.5b`; Task 8 fixes it.
- **D1 to D5, approved with the defaults:**
  - D1: Ollama not installed → a link to its download page (the open question in AGENTS.md section 14).
  - D2: Start runs `ollama serve` and leaves it running after A.I.D.P quits.
  - D3: a Chat sidebar of conversations, one conversation per workspace folder; no export.
  - D4: Dark, Light and System themes by palette swap.
  - D5: `num_ctx` 8,192, keep-alive choices, the text budget, suggested downloads with sizes.

## 3. Built, changes from the plan, live check, RAM, what's left

Who did what: Antigravity (Gemini) executed Tasks 1 to 11. Claude Code wrote the plan, reviewed Tasks 1 to 5 and 6 to 11, and fixed the findings. The human ran the live check.

### Built

- **History:** migration 4 (`conversations`, `messages`, `models.num_ctx`); the UI saves each message through Rust; each reply stores its model reference and name; Chat has a sidebar (New chat, filter by title, delete with confirmation); each workspace folder keeps one conversation.
- **Ollama:** one built-in connection (fixed `127.0.0.1:11434`, no key) whose models sync from `/api/tags` and `/api/show`; `ollama_chat.rs` with tools, `num_ctx` and `keep_alive`; Start (`ollama serve`, left running) and Get Ollama (system browser, fixed URL); downloads with progress and Cancel, Delete, Free memory, context length per model.
- **Small context windows:** what the panel attaches and what one tool result returns are capped at 2 characters per context token.
- **Picker:** cloud models by connection, local models under `Local · Ollama`, disabled with "(Ollama stopped)"; keys split on the first colon.
- **Settings:** default model, theme (Dark, Light, System by palette swap; editor and terminal follow), keep local models loaded.
- **Docs:** decisions 0013 to 0015, the user guide, security and setup notes; the Ollama-installer question answered.

### Changes from the plan

Found in the two reviews, each fixed test-first:

- Model-name checks on delete and unload; a local model found ahead of a cloud model with the same name; Ollama errors mapped by status (a 500 mentioning "not found" was ModelNotFound); replayed tool arguments always an object (Ollama rejects strings); relative `PATH` entries skipped when finding Ollama; one helper for the 8,192-token default.
- A reply streaming when the user opened another chat was never saved (a probe confirmed it): the chat list now waits during a reply, the AI panel hides Clear, and Chat opens the newest chat only on its first visit.
- Ollama action errors (Start, Get Ollama, Delete, Free memory, context) are shown; a cancelled download is no error; a stored error keeps its message.
- Still open: switching workspace folders mid-reply stops the reply and its partial text isn't saved.
