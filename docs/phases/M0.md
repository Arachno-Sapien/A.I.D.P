## 3. Changes from Original Plan

- **Zustand and @testing-library/react deferred to M1:** Kept M0 strictly focused on app scaffolding, IPC wiring, and the test gate. Zustand and component testing will be introduced with the first chat state in M1.
- **Bindings exported via unit test:** Rather than regenerating bindings at debug app startup, `export_bindings` runs inside `cargo test`. This allows CI to assert that `bindings.ts` has no uncommitted drift.
- **Provisional App Name:** Configured as `aidp` with bundle identifier `com.aidp.desktop`. Display name and branding remain open for final human confirmation before M2.
- **specta versions:** `specta =2.0.0-rc.26` and `specta-typescript =0.0.13` instead of the plan's rc.27 / 0.0.14. Tauri 2.12 itself depends on specta rc.26, so this keeps a single specta version in the tree.
- **Windows test manifest in `build.rs`:** not in the plan. It fixes `0xc0000139` when running `cargo test` on Windows (see `.ai/memory/known-issues.md`). Applied on MSVC targets only.
- **Size-focused release profile:** `[profile.release]` uses `lto`, `codegen-units = 1`, `strip` and `panic = "abort"` (Tauri size guide), giving a 4.3 MB binary. Trade-offs: a panic closes the whole app instead of failing one request, and release builds are slower. Acceptable while clippy denies `unwrap`/`expect`.
