## 2. Decisions made while planning

The full list is in the plan, under "Decided in this plan". The ones that shape the work most:

- **The gate runs on all three OSes** in CI; failures there are fixed before anything is released.
- **A Release workflow started by hand** builds every installer with `tauri-action` and leaves a draft; the human publishes.
- **Updates are signed** with a key only the human holds (GitHub secrets). The updater runs behind the app's own typed commands, so no plugin permission reaches the UI. Updater files are built only in CI, so local builds need no key.
- **macOS and Linux take PATH from the user's login shell** at start, so commands, the terminal and Ollama are found when the app is opened from Finder or a desktop menu.
- **Found while planning:**
  - A macOS app opened from Finder would not find `npm`, `cargo` or `ollama` (minimal PATH).
  - (Corrected in Task 2: the model was already told `sh` on macOS and Linux; the planning search showed only the Windows line.)
  - The design's risk row still said Linux ships after Windows; fixed with decision 0016.
- **D1 to D6, approved with the defaults:**
  - D1: NSIS on Windows, universal `.dmg` on macOS, AppImage and `.deb` on Linux.
  - D2: Windows unsigned; macOS ad-hoc signed, not notarized.
  - D3: check at start (with an off switch) and on demand; install only on click, never with unsaved files.
  - D4: two release candidates published as normal releases to test the update, then 0.1.0.
  - D5: CI on three OSes; an 8 GB Ubuntu VM for the Linux check and the 8 GB box; no Mac hand-check, said in the release notes.
  - D6: all M4 and M5 carry-overs in M6, with full-width characters refused in model commands. (Widened in Task 3 after two automated security reviews: on Windows, every character the ANSI code page does not hold exactly is refused too, since an ANSI program gets it as a best-fit lookalike or the wildcard `?`.)
