# Milestone M4: Agent tools and terminal

Milestone status: **In progress.** The plan was approved by the human on 2026-10-30 with the defaults for D1 (widen the secret-file list), D2 (limits) and D3 (shells).
Plan: [`docs/superpowers/plans/2026-10-30-m4-agent-tools.md`](../superpowers/plans/2026-10-30-m4-agent-tools.md)

## 1. Goal

In the workspace's AI panel, a model with tool calling lists, reads and searches the open folder on its own. It proposes edits and new files, which reach the disk only after Accept, and asks to run commands, which run only after Run. A terminal panel runs the user's own shell in the folder. Models without tool calling keep the M3 workspace (design doc, "Coding workspace").

Done means (design doc, "Milestones"):

- [ ] `ChatEvent::ToolCall` and tool calling in the OpenAI-compatible and Anthropic adapters
- [ ] `list_files`, `read_file`, `search`, `edit_file`, `create_file`, and `run_command` work inside the folder
- [ ] Every edit shows a diff first; every model command asks first; no auto-approve
- [ ] Secret-looking files are never read or sent unless the user adds them by hand
- [ ] The terminal panel runs the user's shell in the folder; model commands have a timeout and Stop
- [ ] Fake-provider tests: a model asking for a path outside the folder is refused, and a denied command never runs
- [ ] Models without tool calling still get the M3 workspace

## 2. Decisions made while planning

The full list is in the plan, under "Decided in this plan". The ones that shape the code most:

- **The tool loop runs in Rust.** Approval depends only on the tool's name, never on the model or a tool result. Read-only tools run at once; edits, new files and commands wait for the user's answer, and no code path answers for them.
- **Each adapter returns its own assistant message,** and the loop sends it back unchanged within one user message. That keeps Claude's thinking blocks valid, which current Claude models require in tool loops. Between user messages, only text is sent.
- **An Agent switch in the AI panel**, defaulting from a new `supports_tools` capability (OpenRouter reports it; Anthropic is always yes; others unknown). With the switch off, the panel is the M3 workspace.
- **Commands** run in the folder with no input, a 120-second timeout, Stop, a kill of the whole process tree, and the last 20,000 characters of output.
- **The terminal** is one `portable-pty` session shown with xterm.js, which loads only when the panel is first opened.
- **D1 to D3, approved with the defaults:**
  - D1: security rule 6 is widened (more secret-looking names, plus a private-key content check). Task 4 changes AGENTS.md and the design doc word for word and writes decision 0010.
  - D2: the limits are 120 s per command, 20,000 characters of output, 100,000 characters per read, 500 list entries, 100 search matches and 25 tool steps.
  - D3: model commands run in `cmd.exe`, and the terminal runs PowerShell (decision 0011).

## 3. Built, changes from the plan, RAM, what's left

### Built
- **Tool-calling gateway layer (`gateway/`):**
  - Extended `ModelProvider::stream_chat` to return `Result<Reply, ProviderError>`.
  - Emits `ChatEvent::ToolCall` and `ChatEvent::ToolResult`.
  - OpenAI-compatible adapter parses streamed tool calls (`call_id`, `name`, `arguments`), normalizes blank arguments to `{}`, and round-trips assistant tool call messages.
  - Anthropic adapter parses `tool_use` blocks, preserves extended thinking signatures in assistant messages, and sends `tool_result` blocks.
  - Integration tests with wiremock covering multi-turn tool calling, error mapping, and dropped streams.
- **Data model migration 3 (`db/`):**
  - Added `supports_tools BOOLEAN` to the `models` table.
  - Automatically populated by `list_models` for OpenRouter and Anthropic; user-configurable in Models management.
- **Workspace tools backend (`tools/`):**
  - `list_files`, `read_file`, `search`, `edit_file`, `create_file`, and `run_command` in `src-tauri/src/tools/`.
  - Confinement to workspace root via `workspace::paths::resolve` and `resolve_new`.
  - Expanded secret shielding (decision 0010) covering credential files and PEM private key detection.
  - Approvals registry (`Approvals`): atomic registration, single-use answering, cancellation token support.
  - Command runner (`command.rs`): runs `cmd.exe /D /S /C` on Windows with 120s timeout, Stop cancellation, whole process-tree kill via `taskkill /F /T /PID`, and last 20,000 character output tail capture.
- **Agent loop (`agent.rs`):**
  - Orchestrates tool execution in Rust.
  - Read-only tools (`list_files`, `read_file`, `search`) execute immediately.
  - Mutating tools (`edit_file`, `create_file`, `run_command`) wait for explicit user approval via `answer_tool`.
  - Hard limit of 25 tool execution steps per interaction; 25th step disables further tool calls.
- **Workspace UI (`features/workspace/`):**
  - AI panel **Agent** toggle switch defaulting based on model `supports_tools`.
  - `ToolStepView` renders interactive cards for tool execution: spinners for running tools, plain-text command cards with Run/Deny buttons, diff review prompts for edits.
  - Editor tab reload for clean tabs upon accepted file edits.
- **Terminal panel (`features/workspace/` & `tools/pty.rs`):**
  - `portable-pty` backend spawning `powershell.exe -NoLogo` on Windows (decision 0011) and `$SHELL` on Unix.
  - Robust UTF-8 stream decoding (`take_utf8`) and ConPTY lifecycle management.
  - Lazy-loaded frontend component with `@xterm/xterm` and `@xterm/addon-fit`, dynamic resize observation, restart button upon process exit, and `Ctrl+\` keyboard shortcut.

### Changes from the plan
- **Search link skipping:** The `ignore` directory walker traverses symlinks to files even when `follow_links(false)` is set. `tools/search.rs` explicitly skips non-regular files to prevent reading outside the workspace through links.
- **Boundary check before file existence:** `workspace::paths::resolve_new` verifies the canonical destination path resides within the workspace root before checking if the file already exists on disk, preventing an existence oracle across links.
- **Over-long line cutting:** `read_file` truncates single lines exceeding `READ_LIMIT` (100,000 characters) to prevent token exhaustion from minified single-line assets.
- **Secret-looking names permitted on file creation:** `prepare_create` allows writing files like `.env.example`, as specified in the plan.
- **Background process pipe holding:** Commands spawning background processes (e.g. `start /b`) keep stdout pipes open after child exit; output reading is raced against Stop cancellation and timeouts.
- **ConPTY EOF handling:** Windows ConPTY does not signal EOF on child exit until `ClosePseudoConsole` is called. A background waiter thread detects child termination and drops the master handle to cleanly emit `Exit`.
