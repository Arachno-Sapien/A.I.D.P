Milestone status: **Done** (closed 2026-10-30 at the human's request). The plan was approved by the human on 2026-10-30 with the defaults for D1 (widen the secret-file list), D2 (limits) and D3 (shells).

## 1. Goal

In the workspace's AI panel, a model with tool calling lists, reads and searches the open folder on its own. It proposes edits and new files, which reach the disk only after Accept, and asks to run commands, which run only after Run. A terminal panel runs the user's own shell in the folder. Models without tool calling keep the M3 workspace (design doc, "Coding workspace").

Done means (design doc, "Milestones"):

- [x] `ChatEvent::ToolCall` and tool calling in the OpenAI-compatible and Anthropic adapters
- [x] `list_files`, `read_file`, `search`, `edit_file`, `create_file`, and `run_command` work inside the folder
- [x] Every edit shows a diff first; every model command asks first; no auto-approve
- [x] Secret-looking files are never read or sent unless the user adds them by hand
- [x] The terminal panel runs the user's shell in the folder; model commands have a timeout and Stop
- [x] Fake-provider tests: a model asking for a path outside the folder is refused, and a denied command never runs
- [x] Models without tool calling still get the M3 workspace

## 2. Decisions made while planning

The full list is in the plan, under "Decided in this plan". The ones that shape the code most:

- **The tool loop runs in Rust.** Approval depends only on the tool's name, never on the model or a tool result. Read-only tools run at once; edits, new files and commands wait for the user's answer, and no code path answers for them.
- **Each adapter returns its own assistant message,** and the loop sends it back unchanged within one user message. That keeps Claude's thinking blocks valid, which current Claude models require in tool loops. Between user messages, only text is sent.
- **An Agent switch in the AI panel**, defaulting from a new `supports_tools` capability (OpenRouter reports it; Anthropic is always yes; others unknown). With the switch off, the panel is the M3 workspace.
- **Commands** run in the folder with no input, a 120-second timeout, Stop, a kill of the whole process tree, and the last 20,000 characters of output.
- **The terminal** is one `portable-pty` session shown with xterm.js, which loads only when the panel is first opened.
- **D1 to D3, approved with the defaults:**
  - D1: security rule 6 is widened (more secret-looking names, plus a private-key content check). Task 4 changes AGENTS.md and the design doc word for word and writes decision 0010.
  - D2: the limits are 120 s per command, 20,000 characters of output, 100,000 characters per read, 500 list entries, 100 search matches and 25 tool steps.
  - D3: model commands run in `cmd.exe`, and the terminal runs PowerShell (decision 0011).

## 3. Built, changes from the plan, live check, RAM, what's left

Who did what: Antigravity (Gemini) executed Tasks 1 to 11. Claude Code wrote the plan, reviewed Tasks 1 to 7 and 8 to 11, and fixed the findings. The human ran the live check.

### Built

- **Gateway (`gateway/`):** `stream_chat` returns `Reply` (usage, tool calls, the provider's own assistant message). `ChatEvent::ToolCall` and `ToolResult`. The OpenAI-compatible adapter assembles streamed tool calls by index, keeps unknown keys (Gemini's thought signature), names missing ids `call_{index}`, and treats blank arguments as `{}`. The Anthropic adapter keeps every block, thinking and redacted thinking included, and sends `max_tokens` 32,000 with tools. A provider that refuses tools gets one clear message.
- **Capability (`db/`):** migration 3 adds `supports_tools INTEGER` (NULL unknown, 0 no, 1 yes), filled for OpenRouter from `supported_parameters` and always yes for Anthropic. There is no Models-page control; the Agent switch is the user's override.
- **Tools (`tools/`, `workspace/`):** `list_files`, `read_file`, `search`, `edit_file`, `create_file`, `run_command`. Every path goes through `resolve` or `resolve_new`; the secret filter covers names (rule 6, decisions 0010 and 0012) and private-key content; `.git` is off limits. Edits replace text that occurs exactly once and keep the file's line endings and BOM.
- **Approvals and the loop:** `Approvals` registers before its event; every call gets one result; Stop or a folder switch ends a waiting approval as Stopped. Up to 25 model calls per message.
- **Command runner:** `cmd.exe /D /S /C` on Windows, no input, 120 s timeout, Stop, `taskkill /T /F`, the last 20,000 characters; reading the output is part of the race against Stop and the timeout.
- **UI (`features/workspace/`):** the Agent switch, step cards (the command and folder stay on the card), tool diffs through the M3 diff view, a clean tab reloads after an accepted edit, and M3's Apply waits while a tool proposal is open.
- **Terminal:** `portable-pty` running PowerShell in the folder, xterm.js loaded on first open, Restart after exit; a new folder starts a new shell. Extras beyond the plan: `Ctrl+\` toggles the panel and the panel can be resized by dragging.

### Changes from the plan

Found in the two reviews and the automated security reviews, each fixed test-first:

- `search` read through file links (to `.env` and outside the folder); it now reads regular files only. Unreadable entries are skipped instead of failing the call.
- `resolve_new` answered "already exists" for files outside the folder through a link; it checks the boundary first.
- `read_file` sent a one-line minified file whole; a line over the limit is cut.
- `create_file` refused secret-looking names such as `.env.example`; the plan allows them.
- A command that left a background process holding its output ignored Stop and the timeout.
- The Anthropic adapter could panic (and abort the release app) on a malformed block.
- **Rule 6 widened again (decision 0012, human-approved):** `.git` is refused for every workspace command and tool, also through links and under names Windows trims (`.git.`), and PGP and PuTTY private keys and `*.ppk` count as secret.
- **Commands with hidden characters are refused** before an approval card appears: controls (a lone CR included), every default-ignorable code point (bidi controls, zero-width, variation selectors, tags), separators and private use. Otherwise the card could read differently from what runs.
- The dev terminal showed a stray "[process exited]" (StrictMode opens twice); replaced shells are now ignored and open and close run in order.
- Finished command cards hid the command (found in the live check) and showed "Exit code 0" for an unknown code.
- The test helper's temp folders collided between parallel tests and caused random failures; names are now unique.
