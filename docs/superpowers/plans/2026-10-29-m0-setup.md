# M0 Setup Implementation Plan

> **For agentic workers:** execute task by task, in order. The tasks share files (`package.json`, `vite.config.ts`, `Cargo.toml`, `lib.rs`), so run them inline in one session rather than in parallel subagents. In Claude Code, `superpowers:executing-plans` fits; in other tools, follow the steps directly. Steps use checkbox (`- [ ]`) syntax for tracking.

> Revised 2026-10-29 by Claude Code (Opus 5.5) after review of the first draft by Antigravity (Gemini 3.8 Flash): stale crate pins, scaffold naming, gate order, CSP/opener, no-`expect` enforcement, bindings generation, per-task commits, line endings, CI prerequisites.

**Goal:** Close Milestone M0: a Tauri 2 + React + TypeScript + Vite app that opens a window, with typed IPC (tauri-specta), Tailwind, Vitest, the four-check gate passing locally, CI defined, and the M0 docs written.

**Architecture:** The React frontend talks to the Rust core only through generated `commands` in `src/lib/bindings.ts` (tauri-specta). Tailwind for styling, no component library. Vitest for frontend tests, `cargo test` for Rust.

**Tech stack:** Tauri 2, React, TypeScript, Vite, Tailwind CSS v4, tauri-specta, Vitest, Rust 1.99 (MSVC), GitHub Actions.

**Spec:** [`docs/design.md`](../../design.md) (still at the repo root as `Desktop AI Model App Design Doc.md` until Task 4 moves it).

## Global constraints

- **The gate** (AGENTS.md section 8): `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`, `cargo test --manifest-path src-tauri/Cargo.toml`, `npm run typecheck`, `npx vitest run`. All four green before every commit.
- **Commit at the end of every task** once the gate is green, and update the "In progress" block in `.ai/memory/progress.md` (plan path, task number, next step). This is what lets another agent take over if you run out of tokens. Task 1 is the one exception: it can't be committed until Task 2 adds Vitest (see Task 1, step 8).
- **Never push** without the human's explicit OK.
- No hand edits to `src/lib/bindings.ts`. No `unwrap()`/`expect()` outside tests (Task 1 makes clippy enforce this).
- Every new dependency gets a one-line reason in the commit body.
- Keys and security rules: AGENTS.md section 6. M0 handles no keys, but rule 5 (CSP, unused plugins) applies from the first scaffold.

### Task 2: Typed IPC with tauri-specta, plus Vitest (first scaffold commit)

**Files:** modify `src-tauri/Cargo.toml`, `src-tauri/src/lib.rs`, `src/App.tsx`, `vite.config.ts`, `package.json`; create `src/lib/bindings.ts` (generated) and `src/lib/bindings.test.ts`.

- [ ] **Step 1: Pick matching crate versions.** On 2026-10-29, crates.io had `tauri-specta` 2.0.0-rc.26, `specta` 2.0.0-rc.27 and `specta-typescript` 0.0.14. Confirm they're a matching set in tauri-specta's README or `cargo info tauri-specta`, which also lists feature names. Then pin all three exactly:
  ```bash
  cargo add --manifest-path src-tauri/Cargo.toml tauri-specta@=2.0.0-rc.26 --features typescript
  cargo add --manifest-path src-tauri/Cargo.toml specta@=2.0.0-rc.27
  cargo add --manifest-path src-tauri/Cargo.toml specta-typescript@=0.0.14
  ```
- [ ] **Step 2: Wire the builder, and export bindings from a test.** Generating the file from `cargo test` means CI can check that it's up to date (Task 5), and it's the only place bindings get generated. There's no export at app startup. In `src-tauri/src/lib.rs`:
  ```rust
  use tauri_specta::{collect_commands, Builder};

  #[tauri::command]
  #[specta::specta]
  fn greet(name: &str) -> String {
      format!("Hello, {name}! You've been greeted from Rust!")
  }

  fn specta_builder() -> Builder<tauri::Wry> {
      Builder::<tauri::Wry>::new().commands(collect_commands![greet])
  }

  pub fn run() -> tauri::Result<()> {
      let builder = specta_builder();
      tauri::Builder::default()
          .invoke_handler(builder.invoke_handler())
          .run(tauri::generate_context!())
  }

  #[cfg(test)]
  mod tests {
      use super::*;
      use specta_typescript::Typescript;

      #[test]
      fn export_bindings() {
          specta_builder()
              .export(Typescript::default(), "../src/lib/bindings.ts")
              .expect("failed to export TypeScript bindings");
      }
  }
  ```
  Create `src/lib/` first, then run `cargo test --manifest-path src-tauri/Cargo.toml`. Check that `src/lib/bindings.ts` exists and exports `commands.greet`. If the API differs in the pinned version, follow that version's README and keep the same shape: one builder fn, and the export only in a test.
- [ ] **Step 3: Switch the UI to the bindings.** In `src/App.tsx`, replace `invoke("greet", { name })` with `commands.greet(name)`, imported from `./lib/bindings`. Remove the now-unused `invoke` import.
- [ ] **Step 4: Add Vitest, scoped to `src/`.** Run `npm install -D vitest`. In `vite.config.ts`, add `/// <reference types="vitest/config" />` as the first line and `test: { include: ["src/**/*.test.{ts,tsx}"] }` to the returned config. That keeps Vitest out of `.agents/`, `.claude/` and `src-tauri/target/`.
- [ ] **Step 5: First real test, for the IPC wiring.** It needs no jsdom or testing-library. Create `src/lib/bindings.test.ts`:
  ```ts
  import { describe, expect, it, vi } from "vitest";

  vi.mock("@tauri-apps/api/core", async (importOriginal) => ({
    ...(await importOriginal<typeof import("@tauri-apps/api/core")>()),
    invoke: vi.fn().mockResolvedValue("Hello, Ada!"),
  }));

  import { invoke } from "@tauri-apps/api/core";
  import { commands } from "./bindings";

  describe("generated IPC bindings", () => {
    it("greet calls the Rust command by name with its args", async () => {
      await expect(commands.greet("Ada")).resolves.toBe("Hello, Ada!");
      expect(invoke).toHaveBeenCalledWith("greet", { name: "Ada" });
    });
  });
  ```
  Run `npx vitest run`. Expected: 1 test passes. Then break it on purpose (change `"greet"` to `"gret"`), confirm it fails, and revert.
- [ ] **Step 6: Full gate, then commit** everything from Tasks 1 and 2, including `src/lib/bindings.ts` and `package-lock.json`:
  `M0: scaffold Tauri 2 + React + TS, typed IPC via tauri-specta, Vitest`
  Commit body: why each dependency is there (tauri-specta/specta/specta-typescript: typed IPC per the design; vitest: frontend tests per the design), CSP set, opener removed. Then update `progress.md`.

### Task 5: CI workflow

**Files:** create `.github/workflows/ci.yml`.

- [ ] **Step 1: Create the workflow.** If newer major versions of these actions exist, bump to them.
  ```yaml
  name: CI
  on: [push, pull_request]

  jobs:
    gate:
      runs-on: windows-latest
      steps:
        - uses: actions/checkout@v5
        - uses: actions/setup-node@v5
          with:
            node-version: 22
            cache: npm
        - uses: dtolnay/rust-toolchain@stable
          with:
            components: clippy
        - uses: Swatinem/rust-cache@v2
          with:
            workspaces: src-tauri
        - run: npm ci
        - run: npm run typecheck
        - run: npx vitest run
        - run: cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
        - run: cargo test --manifest-path src-tauri/Cargo.toml
        - name: bindings.ts is up to date
          run: git diff --exit-code -- src/lib/bindings.ts
  ```
  Order matters: typecheck runs before Rust, so it uses the committed `bindings.ts`. Then `cargo test` regenerates it, and the last step fails if the committed copy was stale.
