# M2 Keys and Providers Implementation Plan

> **For agentic workers:** execute task by task, in order, inline in one session (the tasks share files). In Claude Code, `superpowers:executing-plans` fits; in other tools, follow the steps directly. Steps use checkbox (`- [ ]`) syntax. **Get the human's OK on this plan before Task 1. Do not tick any milestone box, in any file, until the human confirms the live check in Task 10. Do not push; the human decides.**

**Goal:** On first launch the app asks for a provider and key, stores the key in the OS keychain, lists the provider's models for the user to pick, and chats through OpenAI-compatible or Anthropic providers. A Models page tests, re-keys and deletes connections. M1's `config.local.json` path is deleted.

**Architecture:** Connection details (provider kind, label, base URL, last 4 characters of the key, chosen models) live in SQLite. The key lives only in the OS keychain behind a small `SecretStore` trait in `secrets.rs`. A `connections.rs` service orchestrates database, keychain and provider: it tests a key by listing the provider's models before saving anything, and rolls back if the keychain fails. Thin Tauri commands call the service. The UI has a first-run "Add a model" flow, a Models page, and a model picker in Chat.

**Tech stack:** keyring 4.2 (default features), rusqlite 0.41 (`bundled`), plus what M1 added. Frontend: the M1 stack, plus `remark-gfm` if the human agrees (Task 8).

**Spec:** [docs/design.md](../../design.md): "Model layer", "API key security", "Data model", "Flow: add a cloud model", "Milestones -> M2". Rules: [AGENTS.md](../../../AGENTS.md) sections 4, 6 and 7. Carry-overs: [docs/phases/M1.md](../../phases/M1.md) "What's left".

## Global Constraints

- **Workflow:** the gate (AGENTS.md section 8) before every commit; one commit per task (Tasks 6 to 8 share one, see Task 6 step 4); update `.ai/memory/progress.md` after each; every new dependency gets a one-line reason in its commit body.
- **Rust:**
  - No `unwrap()` or `expect()` outside tests (clippy enforces it).
  - Never hold a `std::sync::Mutex` guard across an `.await` (clippy's `await_holding_lock` fails the gate). Lock, do the database work, drop, then await.
- **The key (AGENTS.md section 6, word for word):**
  - It is a `SecretString` from the moment it arrives. No type that holds a plain-text key derives `Debug` or `Serialize`. `NewConnection` gets a hand-written `Debug` that prints `[REDACTED]` for the key.
  - Only `secrets.rs` calls the `keyring` crate. Only the provider adapters call `expose_secret()`.
  - No command returns a key. `ConnectionView` carries `key_hint` only: the last 4 characters, or an empty string when the key is shorter than 12 characters.
  - Cloud URLs use https. Plain http is allowed only for localhost and private addresses (`gateway::url::check_base_url`); anything else is refused with `AppError::InsecureUrl` before any request.
  - If the keychain is unavailable the command fails with `AppError::Keychain` and saves nothing. There is no plain-text fallback.
  - No new Tauri plugin or capability. `tauri.conf.json` and `src-tauri/capabilities/` do not change.
- **64-bit integers cannot cross the IPC** (specta rejects them): ids and timestamps are `u32`.
- **`src/lib/bindings.ts`** is regenerated by `cargo test`, committed, never edited by hand.
- **Verified against sources on 2026-10-29** (do not re-research; if the compiler disagrees, trust the compiler):
  - Anthropic raw HTTP (the claude-api skill's curl reference, since Rust has no official SDK): `POST {base}/messages` with headers `x-api-key`, `anthropic-version: 2026-10-21`, `content-type: application/json`; `max_tokens` is required. Stream events: `message_start`, `content_block_start`, `content_block_delta` (`delta.type == "text_delta"`, `delta.text`), `content_block_stop`, `message_delta` (`delta.stop_reason`, `usage.output_tokens`), `message_stop`. Error body: `{"type":"error","error":{"type":"...","message":"..."}}`. Error types: 400 `invalid_request_error`, 401 `authentication_error`, 403 `permission_error`, 404 `not_found_error`, 413 `request_too_large`, 429 `rate_limit_error`, 500 `api_error`, 529 `overloaded_error`. `GET {base}/models` returns `data[]` with `id`, `display_name`, `max_input_tokens` (the context window).
  - keyring 4.2: `keyring::Entry::new(service, user)`, `.set_password(&str)`, `.get_password()`, `.delete_credential()`; errors are `keyring::Error` (`NoEntry`, `NoStorageAccess`, `PlatformFailure`, `NoDefaultStore`, ...). The default feature `v1` picks the OS store per target (Windows Credential Manager, macOS Keychain, Linux Secret Service), so no platform features are needed.
  - rusqlite 0.41: SQLite is bundled only with the `bundled` feature.
- **Assumed, not verified (fake-server tests only):** `GET {base}/models?limit=1000` is honoured by Anthropic (the default page is 20, so without it long lists are cut); the in-stream `error` event shape above.

## Decided in this plan (record them in docs/phases/M2.md)

- **Keychain behind a trait.** `SecretStore` with `Keychain` (real) and `MemoryStore` (tests, also `pub` so integration tests can use it). Tests never touch the real Credential Manager.
- **Entry naming:** service `com.aidp.desktop`, user `connection-{id}`.
- **Ids are SQLite rowids exposed as `u32`; timestamps are epoch seconds as `u32`** (valid until 2106; specta rejects 64-bit integers).
- **Database:** `{app_data_dir}/aidp.db`. Tables `connections` and `models` only. Migrations are numbered SQL strings applied with `PRAGMA user_version`, no extra crate. `conversations`, `messages` and `settings` arrive with M5. The `models` table has only the columns M2 uses; capability columns come in a later migration (M4). No SQL `CHECK` on `kind`, because SQLite cannot alter a CHECK when M5 adds `ollama`.
- **One shared `reqwest::Client`** in app state (10 s connect timeout). List and test requests also get a 15 s total timeout. Streaming requests get none.
- **Commands that touch the database or keychain are plain `fn`.** Tauri runs them on the main thread, and both take milliseconds. `// ponytail:` upgrade to `spawn_blocking` if the UI ever stutters.
- **`max_tokens` for Anthropic is a constant 8192** (a ceiling that fits every current model; long replies are cut there). `// ponytail:` read the per-model `max_tokens` from the Models API if it bites.
- **The Models page is the connection settings surface.** M5's Settings adds a link to it.
- **No import of the old `config.local.json`.** The human re-adds the connection in the app, then deletes the file.

## Review Focus

1. **A failed test must save nothing.** A wrong key gives an error, no connection row and no keychain entry. Test: Task 5 `failed_test_saves_nothing`.
2. **The keychain entry disappears behind the app's back** (deleted in Credential Manager). Chat shows "The key for this connection is missing... Replace it on the Models page." and does not crash. Tests: Task 5 `missing_key_is_reported`, Task 7 `appErrorText` copy.
3. **The keychain is unavailable** (Linux without Secret Service, locked store). A clear error, nothing saved, no plain-text fallback. Test: Task 5 `keychain_failure_rolls_back_the_row`.

**Behaviour this task pins:**

*Request*
- `POST {base}/messages` with the key as `x-api-key` (header marked sensitive), `anthropic-version`, JSON body `{"model", "max_tokens": 8192, "stream": true, "messages": [...]}`.
- Messages with `Role::System` are not sent as messages: their contents, joined with `"\n\n"`, become the top-level `"system"` string, which is omitted when there are none.

*Stream*
- `content_block_delta` with `delta.type == "text_delta"` -> `Delta(text)`; other delta types (`thinking_delta`, `input_json_delta`) and unknown event types are ignored.
- `message_start` -> `tokens_in` from `message.usage.input_tokens`. `message_delta` -> `tokens_out` from `usage.output_tokens`.
- `message_stop` -> `Step::Done`. A `message_delta` whose `delta.stop_reason` is `"refusal"` -> `Err(Provider { message: "The model declined to answer this request." })`.
- An `error` event -> `map_error_type(type, message)`: `authentication_error` and `permission_error` -> `InvalidKey`; `rate_limit_error` -> `RateLimited { retry_after_secs: None }`; `not_found_error` -> `ModelNotFound`; anything else -> `Provider { message }`. Deltas already sent stay sent.
- Cancel, dropped stream and `out.send` failure behave as in M1 (via `read_sse`).

*HTTP errors before the stream:* `map_http_error` with the body's `error.message` as detail.

*`list_models`:* `GET {base}/models?limit=1000` with the two headers and `LIST_TIMEOUT`. Each `data[]` entry becomes `ModelInfo { id, display_name, context_window: max_input_tokens }`.

### Task 4: Keychain wrapper

**Files:**
- Create: `src-tauri/src/secrets.rs`
- Modify: `src-tauri/src/lib.rs` (`pub mod secrets;`), `src-tauri/Cargo.toml`

**Interfaces:**
- Dependency: `keyring = "4"`. Reason for the commit body: the design's key storage (Windows Credential Manager, macOS Keychain, Linux Secret Service); version 4's default feature selects the store per target.
- `pub const SERVICE: &str = "com.aidp.desktop";`
- `#[derive(Debug, Clone, PartialEq)] pub enum SecretError { NotFound, Unavailable(String) }`
- `pub trait SecretStore: Send + Sync { fn set(&self, id: u32, key: &SecretString) -> Result<(), SecretError>; fn get(&self, id: u32) -> Result<SecretString, SecretError>; fn delete(&self, id: u32) -> Result<(), SecretError>; }`
- `pub struct Keychain;` implements `SecretStore` with `keyring::Entry::new(SERVICE, &format!("connection-{id}"))`. `get` maps `keyring::Error::NoEntry` to `NotFound`; every other error becomes `Unavailable(e.to_string())`. `delete` treats `NoEntry` as success.
- `#[derive(Default)] pub struct MemoryStore` (a `Mutex<HashMap<u32, String>>` inside) implements `SecretStore` and adds `pub fn failing() -> Self` (every `set` returns `Unavailable("keychain locked")`), `pub fn contains(&self, id: u32) -> bool`, `pub fn len(&self) -> usize`, `pub fn remove(&self, id: u32)` (simulates a deletion in Credential Manager).
- `pub fn key_hint(key: &SecretString) -> String`: the last 4 characters when the key has at least 12 characters, else `""`.

**Behaviour this task pins:**
- **`add_connection`**, in this order:
  1. Trim the label; a blank label or an empty key -> `InvalidInput`.
  2. Strip a trailing `/` from the base URL; `check_base_url` is `None` -> `InsecureUrl`.
  3. Move the key into a `SecretString` at once.
  4. Build the provider and call `list_models`. An error returns `Provider { error }` and nothing has been saved.
  5. Insert the row with `key_hint` and the test result.
  6. `secrets.set`. If it fails, delete the row and return `Keychain { message }`.
  7. Return the new view and the available models.
- **`test_connection`:** load the key, call `test_connection`, record `last_test_ok` and the time, return the result.
- **`replace_key`:** test the new key first. Only on success: `secrets.set`, update `key_hint`, record the test. A failure leaves the old key untouched.
- **`delete_connection`:** `secrets.delete(id)` first (a missing entry counts as deleted), then the row. A keychain failure returns `Keychain` and keeps the row so the user can retry. An unknown id -> `NotFound`.
- **`stream`:** load the connection (`NotFound`) and the key (`SecretError::NotFound` -> `KeyMissing`, other errors -> `Keychain`), then `provider(...).stream_chat(...)`; a provider failure -> `Provider { error }`.
- **Errors:** `SecretError::Unavailable(m)` -> `Keychain { message: m }`; a `rusqlite` error -> `Storage { message }`.
- The lock on `db` is never held across an `.await`.
