**Goal:** Local Ollama models work like cloud models in Chat and the workspace (detected, started, downloaded, deleted, unloaded from the app); chats and the workspace conversation survive a restart with each message's model recorded; a Settings screen sets the default model, the theme and how long local models stay loaded.

**Architecture:** Ollama is one built-in row in `connections` (kind `ollama`, fixed base URL, no key). Its downloaded models are synced into `models` from `/api/tags` and `/api/show`, so the picker, the default model and each message's model work the same for every provider. A new `ollama_chat.rs` adapter talks to `/api/chat` (newline-delimited JSON, tools, `num_ctx`, `keep_alive`) behind the same `ModelProvider` trait. The rest of the Ollama API (status, start, pull, delete, unload, loaded) lives in `src-tauri/src/ollama/`. History is two new tables; the UI decides when to save, and only Rust writes SQLite. The theme swaps Tailwind's neutral palette through CSS variables.

**Tech stack:** what M4 has. No new crate, npm package or Tauri plugin.

**Spec:** [docs/design.md](../../design.md): "Model layer", "Local models (Ollama)", "Data model", "Screens and user flows" (Chat, Models, Settings, "Flow: connect Ollama"), "Milestones → M5", "Risks". Rules: [AGENTS.md](../../../AGENTS.md) sections 4, 6 and 7. Carry-overs: `docs/phases/M3.md` and `docs/phases/M4.md`, "What's left → To M5".

## Global Constraints

- **Workflow:** the gate (AGENTS.md section 8) before every commit; one commit per task; update `.ai/memory/progress.md` after each.
- **Rust:** no `unwrap()`/`expect()` outside tests; never hold a `std::sync::Mutex` guard across `.await`; 64-bit integers never cross the IPC: sizes are whole megabytes (`u32`, rounded up), times are seconds (`u32`), keep-alive is seconds (`i32`).
- **Ollama:**
  - Base URL is the constant `OLLAMA_URL = "http://127.0.0.1:11434"` (design). Plain http to localhost is allowed by `check_base_url`. No user-entered Ollama URL in v1.
  - Ollama has no key: `provider_for` never reads the keychain for it, and no keychain entry is ever written for it.
  - A model name from the UI is checked with `valid_model_name` before any request: 1 to 200 characters from `A-Z a-z 0-9 . _ : / -` (covers `qwen2.5-coder:1.5b` and `hf.co/user/repo:Q4_K_M`).
  - Starting Ollama and opening the download page use `std::process::Command` with a fixed program path or the fixed URL constant `OLLAMA_DOWNLOAD_URL = "https://ollama.com/download"`, never text from the UI or a model. Windows: `CREATE_NO_WINDOW` (`0x0800_0000`), stdio null.
  - **Model ids contain `:`** (`qwen2.5-coder:1.5b`). Any `"{connectionId}:{modelId}"` key is split on the **first** `:` only.
- **History:** only Rust touches SQLite (AGENTS.md section 4). The stored `content_parts` is JSON written by the UI and kept opaque by Rust. Chat history is stored unencrypted in `aidp.db`; it may contain file text the user attached. Keys are never part of it.
- **`src/lib/bindings.ts`** is regenerated by `cargo test`, committed, never edited by hand. Component tests register `afterEach(cleanup)`. CodeMirror stays only in `cm.ts`, xterm only in `term.ts`.
- **Verified against sources on 2026-10-30** (do not re-research; if the compiler or a live check disagrees, trust them):
  - Ollama API (`docs/api.md` in ollama/ollama, and docs.ollama.com tool calling):
    - `POST /api/chat`: `model`, `messages`, `tools`, `options` (`num_ctx`), `stream`, `keep_alive` (default 5 minutes; numbers are seconds, `0` unloads, negative keeps loaded). Streaming is newline-delimited JSON objects: `{"message":{"role","content","thinking"?,"tool_calls"?},"done":false}`; the last has `"done":true`, `done_reason`, `prompt_eval_count`, `eval_count`.
    - Tool calls: `message.tool_calls: [{"function":{"name","arguments":{...object...}}}]`, no id. Several calls can come in one reply (collect them across chunks). Results go back as `{"role":"tool","tool_name","content"}` after the assistant message `{"role":"assistant","content","thinking"?,"tool_calls"}`.
    - Unload: `POST /api/chat {"model","messages":[],"keep_alive":0}`.
    - `GET /api/tags` → `{"models":[{"name","model","size","digest","modified_at","details":{"parameter_size","quantization_level",...}}]}`.
    - `POST /api/show {"model"}` → `capabilities` (strings; `"tools"` per `types/model/capability.go`), `model_info` with an architecture-prefixed `"<arch>.context_length"`.
    - `GET /api/ps` → `{"models":[{"name","size","size_vram","expires_at",...}]}`.
    - `POST /api/pull {"model","stream":true}` → lines `{"status"}` or `{"status","digest","total","completed"?}`, last `{"status":"success"}`; a cancelled pull resumes later.
    - `DELETE /api/delete {"model"}` → 200, or 404 when missing. `GET /api/version` → `{"version"}`.
    - Errors: `{"error":"model 'x' not found"}` with 404 (`server/routes.go`).
  - Download sizes (ollama.com/library/qwen2.5-coder/tags): `qwen2.5-coder:0.5b` 398 MB, `:1.5b` 986 MB, `:3b` 1.9 GB, `:7b` 4.7 GB; the model has the tools badge.
  - Tailwind 4.3.3 neutral palette (`node_modules/tailwindcss/theme.css`): 50 `oklch(98.5% 0 none)`, 100 `97%`, 200 `92.2%`, 300 `87%`, 400 `70.8%`, 500 `55.6%`, 600 `43.9%`, 700 `37.1%`, 800 `26.9%`, 900 `20.5%`, 950 `14.5%`; white `#fff`, black `#000`. Utilities read these variables.
- **Assumed, not verified (check where the task says):** Ollama's default Windows install path is `%LOCALAPPDATA%\Programs\Ollama\ollama.exe` (Task 4 also searches `PATH`; Task 12 confirms); `ollama serve` answers `/api/version` within 15 seconds; a model without tools answers 400 with "does not support tools" (the M4 mapping catches "tool" + "support").

## Before you start (human)

- **D1, Ollama not installed (open question, AGENTS.md section 14).** Default: the Local panel says Ollama isn't installed and a **Get Ollama** button opens `https://ollama.com/download` in the system browser (Rust launches it with the fixed URL; no plugin). The alternative, downloading and running the installer from inside the app, means fetching and starting an executable, which needs its own security review. Default: **link** (decision 0013, which also removes the question from AGENTS.md section 14).
- **D2, starting Ollama.** Default: **Start** runs `ollama serve` with no window, waits until it answers, and leaves it running when A.I.D.P quits (Ollama's own tray app behaves the same; loaded models still unload on keep-alive). The alternative is stopping it on quit when A.I.D.P started it.
- **D3, what history keeps.** Default: Chat gets a sidebar of conversations (New chat, delete with confirmation, filter by title) and opens the most recent one at start. The workspace AI panel keeps one conversation per folder, restored when the folder opens; its Clear deletes it. Not in M5: export (still an open question), a history-location setting, renaming, searching message text.
- **D4, theme.** Default: Dark (today's look, the default), Light and System. Light swaps the neutral palette and white/black through CSS variables (plus darker red, amber and green text), and switches CodeMirror to its default light theme and xterm to light colours. The alternative is hand-written light styles for every component: more polish, far more work.
- **D5, local model defaults.** Default:
  - Context length (`num_ctx`): 8,192 tokens, or the model's maximum if smaller; set per model on the Local panel (2,048 / 4,096 / 8,192 / 16,384 / 32,768, up to the maximum).
  - Keep loaded (`keep_alive`): Ollama's own default, with the choices 5 minutes, 30 minutes, 1 hour, until Free memory, and unload after each reply.
  - Text budget for small context windows: what the AI panel attaches and what one `read_file` or command result returns are each capped at 2 characters per context token (16,384 characters at 8,192 tokens), never above M4's limits.
  - Suggested downloads: `qwen2.5-coder:1.5b` (986 MB, recommended), `:0.5b` (398 MB), `:3b` (1.9 GB), `:7b` (4.7 GB), shown with sizes before downloading. While downloading, a model over 4 GB shows "Needs about 8 GB of free memory", and over 8 GB "Too large for most machines without a GPU".

## Decided in this plan (record them in docs/phases/M5.md)

- **Ollama is a connection.** One `kind = 'ollama'` row, created on first detection (`ensure_ollama_connection`), label `Ollama (local)`, `key_hint` empty. It is hidden from the cloud connections list and has no Test or Delete; the Local panel manages it.
- **Local models are synced, not chosen.** After detection, Start, a finished pull and a delete, `sync_local_models` replaces the Ollama rows in `models` from `/api/tags` + `/api/show` (tools and maximum context). The default model and each model's `num_ctx` survive a sync. When Ollama stops, its models stay in the picker, disabled, with "(Ollama stopped)".
- **Per-request options travel in `ChatRequest.local`** (`num_ctx`, `keep_alive`), filled by `Services` from the model row and the setting. Cloud adapters ignore it.
- **The UI decides when to save:** the user message when it is sent, the assistant message when its reply ends (`done` or `error`, so stopped and failed replies are kept with their status). A reply still streaming when the app closes is lost.
- **`content_parts`** is `{"v":1,"text","content"?,"chips"?,"parts"?,"target"?}` from `chat/persist.ts`. Anything else read back becomes a text-only message from `text`, or an empty one.
- **Each assistant message stores `model_ref`** (`"{connectionId}:{modelId}"`) **and `model_name`** (the display name then), so it still says which model wrote it after a connection is deleted. The message list shows the name above each reply.
- **Not added from the design's `conversations` row:** `model_ref` and `system_prompt` (each message has its model; nothing sets a per-chat prompt). The design's "Data model" is updated to say so.
- **One pull at a time.** A second pull while one runs is refused ("A download is already running."). Cancel drops the request; Ollama resumes it next time.
- **Settings are typed commands,** not a key-value bridge: the UI can only set a `Theme` or a `KeepAlive` value.
- **The picker key fix:** today the picker splits `"3:qwen2.5-coder:1.5b"` on every `:` and loses part of the name. `parseModelKey` splits on the first `:`.

### Task 4: Ollama in the app (connection, sync, commands)

**Produces:**
- `connections.rs`:
  - `Services` gets `ollama_url: String` (`OLLAMA_URL` in `new`), `with_ollama_url(self, url) -> Self` for tests, and `ollama(&self) -> Ollama` (its HTTP client and URL) for the commands.
