# M7 Outside Tools: MCP Client and Browser Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Any model can run this plan.** Every task names its files, signatures, exact strings and tests. Read `AGENTS.md` first (sections 1, 7, 8, 9), then only the task you are on and the "Shared reference" section. Do not start Task 1 until the human has answered Task 0.

**Goal:** Let the Workspace agent call tools from MCP servers the user connects by hand, each call approved first, and ship Microsoft's Playwright MCP server as a one-click preset so the agent can check a locally running web app in a browser.

**Architecture:** A small hand-written MCP client in Rust (`src-tauri/src/mcp/`) speaks JSON-RPC over a child process's stdin/stdout. A `Hub` starts servers when an agent run needs them and stops them when idle. The agent loop (`tools/agent.rs`) adds the servers' tools to the six built-in ones under the name `mcp__<server>__<tool>` and routes those calls through the existing `Approvals`. Browser checks are not new Rust code: they are one preset command line for the Playwright MCP server, plus docs.

**Tech Stack:** tokio (`process`, `io-util`, `sync`, `time`, already in `Cargo.toml`), serde_json, rusqlite, tauri-specta. **No new Rust crate and no new npm package.** At run time the preset needs Node 18+ on the user's machine (`npx`).

**Spec:** `docs/design.md` section "Later" (lines 498–499: "MCP client", "Browser checks with Playwright") and "Workspace and tool security"; `AGENTS.md` sections 4, 6, 7.

## Review Focus

Failure modes the spec implies that are most likely to bite a user. Each has a named test in the task that owns the code.

1. **A server prints logs or junk on stdout** (many do at start). Expected: the line is skipped, the session carries on. Test: `non_json_and_notifications_are_skipped` (Task 2).
2. **A server dies or hangs mid-call, or `npx` is still downloading when the user presses Stop.** Expected: the call ends at once with a clear message, the process tree is gone, the next run starts it again. Tests: `closed_stream_fails_pending_request`, `stop_sends_cancelled` (Task 2); `server_death_fails_call_and_restarts`, `stop_during_start_kills_the_process` (Task 4).
3. **A huge result or one endless line.** Expected: the model gets at most 20,000 characters with a cut note; a line over 8 MB closes the session; the app's memory stays flat. Tests: `oversized_line_closes` (Task 2), `mcp_result_is_cut` (Task 5).
4. **Tool names or schemas a provider rejects** (names with dots or over 64 characters, a schema that isn't an object, duplicates). Expected: such tools are skipped or normalised so the provider never returns 400. Tests: `tool_name_table`, `schema_is_normalised`, `to_specs_skips_and_cuts` (Task 3).
5. **A tool result or description that tells the model to do something** (a web page saying "run this command"). Expected: nothing runs without an approval card showing the exact arguments, hidden characters shown as `\u{...}`. Tests: `mcp_call_waits_for_approval_and_returns_text`, `declined_mcp_call_is_not_sent`, `arguments_show_hidden_characters` (Task 5).

## Shared reference

### MCP on the wire (all a client needs)

Each message is one line of JSON ending in `\n`, UTF-8, no line breaks inside. The client writes to the server's stdin and reads its stdout. stderr is free-form logs.

```jsonc
// 1. client → server
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"aidp","version":"<CARGO_PKG_VERSION>"}}}
// 2. server → client (protocolVersion may be an older one the server picks)
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{}},"serverInfo":{"name":"x","version":"1"}}}
// 3. client → server (a notification: no id, no reply)
{"jsonrpc":"2.0","method":"notifications/initialized"}
// 4. list tools; repeat with {"cursor": nextCursor} while the result has nextCursor
{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}
{"jsonrpc":"2.0","id":2,"result":{"tools":[{"name":"echo","description":"…","inputSchema":{"type":"object","properties":{}}}],"nextCursor":"abc"}}
// 5. call a tool
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"echo","arguments":{"text":"hi"}}}
{"jsonrpc":"2.0","id":3,"result":{"content":[{"type":"text","text":"hi"}],"isError":false}}
// failure of the request itself
{"jsonrpc":"2.0","id":3,"error":{"code":-32602,"message":"Unknown tool"}}
// client gives up on a request (timeout or Stop)
{"jsonrpc":"2.0","method":"notifications/cancelled","params":{"requestId":3,"reason":"stopped"}}
// the server may ask the client things: answer ping with {}, everything else with an error
{"jsonrpc":"2.0","id":"s1","method":"ping"}        → {"jsonrpc":"2.0","id":"s1","result":{}}
{"jsonrpc":"2.0","id":"s2","method":"roots/list"}  → {"jsonrpc":"2.0","id":"s2","error":{"code":-32601,"message":"Method not found"}}
```

Accepted `protocolVersion` answers: `"2025-06-18"`, `"2025-03-26"`, `"2024-11-05"`. Anything else: disconnect.

**Behaviour the tests pin (write the body from these):**

- Reader task: read bytes up to `\n`. A line longer than `MAX_LINE_BYTES` → mark closed, fail every pending request with `Protocol { message: "a message over 8 MB".into() }`, stop reading. A line that isn't JSON, or is JSON with `method` and no `id` (a notification) → skip. JSON with `method` and `id` (a server request) → write the `ping` or `-32601` answer from "Shared reference", echoing `id` as received (number or string). JSON with `id` and `result` or `error` → send to the waiting `oneshot` (`error` → `McpError::Rpc`; ids the client doesn't know → skip). End of stream → mark closed, fail every pending request with `Closed { stderr: String::new() }` (the Hub fills in stderr).
- Read the line with `tokio::io::AsyncBufReadExt::fill_buf`/`consume` in a loop so the cap is enforced before the bytes are kept; do not use `lines()` or `read_line` (no cap).
- `request`: if closed → `Closed`. Register the `oneshot`, write the line, then `tokio::select!` on the answer, `tokio::time::sleep(timeout)` and `cancel.cancelled()`. On timeout or cancel: remove the pending entry, `notify("notifications/cancelled", {"requestId": id, "reason": "timeout" | "stopped"})` ignoring its error, return `Timeout` / `Stopped`. A write error → `Closed`.
- `initialize`: request `initialize` with the params from "Shared reference" (`env!("CARGO_PKG_VERSION")`), check `result.protocolVersion` is in `ACCEPTED_VERSIONS` (else `Protocol { message: format!("protocol version {v}") }`), then `notify("notifications/initialized", None)`.
- `list_tools`: request `tools/list` with `{}`, then with `{"cursor": c}` while `nextCursor` is a non-empty string; stop after 20 pages. Each tool: `name` (string, required: skip the tool if missing), `description` (string or `""`), `inputSchema` (kept as is). No filtering here; Task 3 does that.
- `call_tool`: request `tools/call` with `{"name": name, "arguments": arguments}` → `CallResult { text: flatten(&result["content"]), is_error: result["isError"] == true }`.
- `flatten`, per item `type`: `text` → its `text`; `image` → `[image {mimeType}, not shown]`; `audio` → `[audio {mimeType}, not shown]`; `resource` → `resource.text` if a string, else `[file {resource.uri}, not shown]`; `resource_link` → `[link {uri}]`; anything else, or `content` not an array → `[content not shown]`. Missing fields read as empty strings.

**Behaviour:**

- `start`: `create_dir_all(base/name)` (error → `Start`); `shell_command(&config.command)` with `current_dir`, stdin/stdout/stderr piped, wrapped in `tokio::process::Command::from`, `kill_on_drop(true)`; spawn (error → `Start { message: e.to_string() }`). Take the three pipes. On Windows `Job::holding(&child)`. Spawn a task that reads stderr to the end keeping only the last `STDERR_TAIL_BYTES` bytes in the shared buffer (it must always drain, or a chatty server blocks). `Client::new(stdout, stdin)`, then `initialize(START_TIMEOUT, cancel)` and `list_tools(LIST_TIMEOUT, cancel)`. On any error: kill (below) and return it; a `Closed` gets `stderr` = the tail as lossy UTF-8, trimmed, last 500 characters. On success insert into the map.
- Kill (used by start failure, `stop`, `stop_all`, `stop_idle`): remove from the map, `kill_tree(pid).await`, drop the job (Windows), `child.start_kill()` ignoring the error, `child.wait()` raced against 2 s. Dropping the `Client` closes stdin.
- `call`: look up by `split_name`; check the tool is one `to_specs` kept; clone the `Arc<Client>` and set `last_used` while holding the lock, **release the lock**, then `client.call_tool(tool, arguments, timeout, cancel)`. On `Closed`: fill `stderr` as in `start`, and kill the entry so the next `start` begins fresh.
- Never log the command line, the arguments or the results.

## Deliberately left out (and when to add it)

- **Tokens / env vars for servers**: add when the human wants a server that needs a key. They belong in the keychain through `secrets.rs`, never in SQLite.
- **HTTP (Streamable HTTP / SSE) servers**: add when a wanted server has no stdio mode. It brings network rules (HTTPS, the URL checks in `gateway/url.rs`).
- **Images from tools**: add together with images in tool results across the three adapters.
- **Resources, prompts, sampling, elicitation, roots**: the client declares none; servers must work with tools alone.
- **`.mcp.json` in the opened folder**: never read (rule 1). A repo must not be able to start programs.
- **Live tool-list updates**: tools are listed once per server start; Test after a restart refreshes them.
