# Chat list, pin and archive, and icons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before rc.2 ships, the human asked for four things: a chat history list that can be hidden and resized, chats that can be pinned, archived or deleted, icons in place of some text buttons, and a skill that helps polish the UI.

**Architecture:** Icons come from one tree-shaken package. The chat list reuses the workspace's `Splitter`. Its open state and width live in a small store, so they survive switching screens. Pin and archive are two columns added by migration 5, set through two thin commands; the frontend groups the list.

**Tech Stack:** React + Tailwind, Zustand, `lucide-react` (new, decision 0018), Rust + rusqlite, tauri-specta.

**Spec:** the human's request of 2026-10-31 (quoted in this task's session log), `docs/design.md` ("Screens and user flows → Chat", "Data model"), AGENTS.md.

## Global Constraints

- No new dependency besides `lucide-react`; its reason goes in the commit and decision 0018.
- Tailwind only, no component library.
- The UI calls only the generated `commands` from `src/lib/bindings.ts`, which is regenerated by `cargo test` and never edited by hand.
- Schema changes go through a numbered migration (this is migration 5).
- No `unwrap()` or `expect()` outside tests.
- Every icon-only button has an `aria-label` and a `title`. The existing accessible names stay as they are: "Files", "AI", "Terminal", "Refresh", "Close folder", "New chat", `Delete ${title}`.
- Keyboard shortcuts act only on the screen that is shown, and a key the editor or terminal already handled (`defaultPrevented`) is theirs.
- Switching chats is blocked while a reply streams. Archive, unarchive and delete are disabled then, with the existing "Wait for the reply to finish" title. Pin stays enabled.
- The gate (clippy `-D warnings`, cargo test, `npm run typecheck`, `npx vitest run`) passes before every commit. Docs change in the same commit as the code they describe.
- The version stays `0.1.0-rc.2`; these changes join its CHANGELOG section.

## Review Focus

1. The newest chat is archived and the app restarts: Chat opens the newest unarchived chat, never the archived one (Task 3, `openPlace` test).
2. The open chat is archived: the next unarchived chat opens, or a new chat, and the archived one isn't in the main list (Task 3, store test).
3. A message is sent in an archived chat: it returns to the main list in Rust and in the store (Task 3, Rust and store tests).
4. A filter typed while chats are pinned and archived applies to every group, including Archived (Task 3, list test).
5. The list is dragged wide and the window then shrinks: the list's max is worked out on each move from the row width minus 360, so the chat column keeps 360 px (Task 2, list width test via keyboard `End`).
