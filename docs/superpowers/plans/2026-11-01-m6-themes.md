# Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Polish the UI with five theme directions for 0.1.0-rc.3: refined Dark and Light, Glass, Soft (neumorphic), Cyber, and Elegant, all chosen in Settings.

**Architecture:** Today the Light theme redefines Tailwind's colour variables under `data-theme`. This plan keeps that idea but moves each theme's colours into one TypeScript table, so they can be tested for contrast. `applyTheme` writes them to `:root` and sets `data-theme` (the theme) and `data-base` (dark or light, for the editor and terminal). Effects that colour alone can't give (blur, soft shadows, glow, serif headings) come from one CSS file keyed by `data-theme`, acting on four hook classes placed on the main surfaces.

**Tech Stack:** React, Tailwind CSS v4 (`@theme` variables), Zustand, Rust `Theme` enum via tauri-specta. No new dependency, and system fonts only.

**Spec:** the human's request of 2026-11-01 ("UI we can polish with some good themes/morphisms"), their choice of all five directions (shown as mock-ups for Refined flat, Glass and Soft; Cyber/digital and Elegant added by the human), `docs/design.md` "Screens and user flows → Settings", AGENTS.md section 3 (Tailwind, no component library).

## Global Constraints

- Tailwind CSS only, no component library, no new dependency.
- Theme colours live in one place, `src/features/settings/themes.ts`; components keep using Tailwind classes (`bg-neutral-950`, `text-neutral-100`, and the new `accent` colour).
- The four hook classes do nothing in Dark and Light: `app-surface` (header, side panels, Models and Settings panels), `app-raised` (message bubbles, cards, buttons), `app-inset` (inputs, composer, code blocks), `app-accent` (Send, the active nav item, the user's message bubble).
- `src/lib/bindings.ts` is regenerated by `cargo test`; the setting stays a string in the `settings` table, and an unknown stored value falls back to Dark.
- The gate passes before every commit; docs change in the same commit.
- Idle RAM stays under 150 MB with the default theme; Glass's numbers are recorded.

## Review Focus

1. A theme saved by a newer version and opened by an older one, or a typo in the setting: the app starts in Dark, not blank (Task 1).
2. Secondary text (`text-neutral-400`/`500`) in Soft and Glass: readable, which the contrast test covers (Task 1).
3. Switching theme while the editor and terminal are open: both recolour without reopening (Task 2).
4. Glass on Linux (WebKitGTK) where blur is slow or missing: panels stay readable because their fill is opaque enough alone (Task 2, fill alpha at least 0.72 over the backdrop).
5. Code blocks in replies: syntax colours stay readable on every theme's code background (Task 2, Prism theme chosen by base).
