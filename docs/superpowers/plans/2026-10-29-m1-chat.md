# M1 Chat With One Cloud Model Implementation Plan

> **Status: completed 2026-10-29.** M1 is closed; see `docs/phases/M1.md`. Do not re-run these tasks.

> **For agentic workers:** execute task by task, in order. Each task builds on the previous one's types, so run them inline in one session rather than in parallel subagents. In Claude Code, `superpowers:executing-plans` fits; in other tools, follow the steps directly. Steps use checkbox (`- [ ]`) syntax. **Get the human's OK on this plan before Task 1.**

**Goal:** Type a message in A.I.D.P and get a streamed reply from one OpenAI-compatible provider, with Stop, Markdown, and code blocks you can copy.

**Architecture:** The Rust core gets a `gateway` module containing:
- the `ModelProvider` trait and the normalized `ProviderError`;
- a byte-safe SSE line parser;
- the OpenAI-compatible adapter (reqwest, streaming).

A thin `send_message` command streams `ChatEvent`s to the UI over a Tauri `Channel`. `stop_reply` cancels the stream through a `CancellationToken`. For M1 only, the base URL, model and key come from `config.local.json` in the app config folder; M2 moves the key into the keychain.

The React side is a Zustand store plus a chat screen. Replies render through react-markdown with raw HTML off, and code blocks are highlighted with Prism.

**Tech stack:** Tauri 2.12, tauri-specta rc.26, reqwest 0.13 (`native-tls`), tokio-util (`CancellationToken`), futures-util, async-trait, secrecy 0.10, wiremock 0.6 (tests). React 19, Zustand 5, react-markdown 10, prism-react-renderer 2, Vitest with @testing-library/react and jsdom.

**Spec:** [docs/design.md](../../design.md): "Model layer", "API key security", "Milestones → M1". Rules: [AGENTS.md](../../../AGENTS.md) sections 4, 6 and 7.

## Global Constraints

- **Workflow:**
  - Run the gate (AGENTS.md §8) before every commit.
  - Commit at the end of each task, and update `.ai/memory/progress.md` (In progress, Next step).
  - Every new dependency gets a one-line reason in its commit body.
- **Rust code:**
  - No `unwrap()` or `expect()` outside tests; clippy enforces this.
  - For a poisoned lock, use `lock().unwrap_or_else(PoisonError::into_inner)`.
- **The key** (AGENTS.md §6, rules 2 and 3):
  - It is a `secrecy::SecretString` from the moment it is read.
  - Never log it, never log request headers, and never return it from a command or put it in an error.
- **`base_url`** (rule 4) must be `https`. Plain `http` is allowed only for localhost or a private-network address, and then the UI shows a warning.
- **No new Tauri plugin or capability permission** (rule 5):
  - Copy uses `navigator.clipboard`.
  - Links in replies never navigate the window.
  - The navigation guard in Task 4 is an in-app plugin with no commands and no permissions.
- **Model replies** render with raw HTML off (rule 6).
- **`src/lib/bindings.ts`** is regenerated by `cargo test`, committed, and never edited by hand.
- **M1 key source:** `config.local.json` in the app config folder (`%APPDATA%\com.aidp.desktop\` on Windows), outside the repo. M2 deletes this path.
- **Names come from the design:**
  - `ModelProvider`; `ChatEvent::{Delta, Done, Error}`;
  - `ProviderError` with kinds `InvalidKey`, `RateLimited`, `ModelNotFound`, `ContextTooLong`, `Offline`, `Provider` and `Cancelled`. The design's catch-all kind "ProviderError" is the `Provider` variant here, to avoid `ProviderError::ProviderError`.

## Decided in this plan (record them in docs/phases/M1.md)

- **reqwest uses `native-tls`** (Windows SChannel). reqwest 0.13's default is rustls with aws-lc-rs, which needs CMake and NASM to build on Windows. Decision record 0006 (Task 2).
- **The M1 trait has only `stream_chat`.** `list_models` and `test_connection` arrive in M2, together with the Models page that uses them.
- **The adapter sends only `Delta`.** The command sends the single `Done` or `Error`, so "exactly one final event" is enforced in one place.
- **No `stream_options` in the request,** because some compatible providers reject unknown fields. Usage is reported only if the provider sends it.
- **M1 chats live in memory only.** Long-list virtualization arrives with history in M5.

## Before you start (human)

- Pick one OpenAI-compatible provider and have its API key, base URL and a model id ready. OpenAI, OpenRouter, Groq and DeepSeek all work. Task 7's manual check needs them.

## Review Focus

1. **A multibyte character split across two network chunks** (an emoji, an accented letter). Expected: it arrives intact, with no panic. Test: Task 1 `utf8_split_across_chunks`.
2. **A provider that closes the stream without `[DONE]`.** Expected: the partial reply stays, marked as an error. Test: Task 2 `dropped_stream_keeps_deltas_and_errors`.
3. **A reply containing raw HTML or a `<script>`.** Expected: shown as text, never run. Test: Task 6 "does not render raw HTML".
4. **Clicking a link in a reply.** Expected: the window stays on the app. Tests: Task 4 `nav_guard_allows_only_app_urls`, Task 6 "does not turn links into navigation".
5. **Send pressed again while a reply streams, or Stop pressed before the first token.** Expected: no second stream, and no orphaned one. Tests: Task 4 `begin_cancels_previous_reply`, Task 5 "ignores send while a reply is streaming".

### Task 2: OpenAI-compatible adapter

**Files:**
- Create: `src-tauri/src/gateway/openai_compat.rs`, `src-tauri/tests/openai_compat.rs`, `docs/decisions/0006-reqwest-native-tls.md`
- Modify: `src-tauri/Cargo.toml`, `src-tauri/src/gateway/mod.rs` (`pub mod openai_compat;`), AGENTS.md §3 (HTTP row), `.ai/memory/known-issues.md`

**Interfaces:**
- Consumes: Task 1 types and `SseLines`.
- Produces:
  - `pub struct OpenAiCompat`
  - `pub fn new(base_url: String, api_key: SecretString) -> Self`, where `base_url` has no trailing slash (for example `https://api.openai.com/v1`)
  - `impl ModelProvider for OpenAiCompat`

**Behaviour this task pins:**

*Request*
- `POST {base_url}/chat/completions`, with header `Authorization: Bearer <key>`.
- JSON body: `{"model": …, "messages": [{"role": "user", "content": "…"}], "stream": true}`.

*Reading the stream*
- `[DONE]` ends the stream normally.
- Each other `data:` payload is JSON. A non-empty `choices[0].delta.content` becomes `out.send(ChatEvent::Delta(text))`.
- A `usage` object (`prompt_tokens`, `completion_tokens`) in any payload fills the returned `Usage`.
- A payload that isn't valid JSON → `Err(Provider { message: "the provider sent data the app could not read" })`.
- The stream ends without `[DONE]`, or reading the body fails midway → `Err(Provider { message: "the connection closed before the reply finished" })`. Deltas already sent stay sent.

*Errors before the stream starts*
- 401 or 403 → `InvalidKey`.
- 429 → `RateLimited`, with `retry_after_secs` from the `Retry-After` header if it parses as an integer.
- 404 → `ModelNotFound`.
- 400 whose body contains `context_length_exceeded` or `maximum context length` → `ContextTooLong`.
- Any other status → `Provider { message: format!("HTTP {status}: {detail}") }`, where `detail` is the first 200 characters of the body's `error.message`, or of the raw body.
- A reqwest connect or timeout error → `Offline`.

*Cancellation and safety*
- While waiting for the response and while reading the stream, `cancel` wins → `Err(Cancelled)`. Use `cancel.run_until_cancelled(future)` if the resolved tokio-util has it (0.7.13 or later). Otherwise use `tokio::select!` and add tokio's `macros` feature to the normal dependencies.
- `out.send` failing (the window went away) → `Err(Cancelled)`.
- Nothing logs the request, its headers, or the key.

- `pub fn load(dir: &Path) -> Result<LocalConfig, ConfigError>`:

  - `http` with host `localhost`, a loopback IP, a private IPv4 address (`Ipv4Addr::is_private`), or an IPv6 loopback or unique-local address → `LocalHttp`;
  - anything else, including other schemes → `InsecureUrl`.

    | `contextTooLong` | `This conversation is too long for the model. Start a new chat.` |
    | `offline` | `Can't reach the provider. Check your internet connection.` |
    | `provider` | `The provider returned an error: {message}` |
    | `cancelled` | `Stopped.` |

  - `export type MessageStatus = "streaming" | "complete" | "stopped" | "error"`
  - `export interface UiMessage { id: string; role: "user" | "assistant"; text: string; status: MessageStatus; error?: ProviderError }`
  - `export const useChatStore`, a Zustand store with state `{ messages: UiMessage[]; streaming: boolean; configError: ConfigError | null; send(text: string): Promise<void>; stop(): Promise<void>; applyEvent(id: string, ev: ChatEvent): void; clear(): void }`
- Behaviour:
  - **`send`:**
    - Do nothing if `streaming` is true or the text is blank.
    - Otherwise append the user message (`complete`) and an assistant placeholder (`streaming`, with id from `crypto.randomUUID()`).
    - History is every earlier message whose status is `complete` or `stopped`, mapped to `ChatMessage { role, content: text }`, plus the new user message.
    - Create `new Channel<ChatEvent>()` with `onmessage = (ev) => applyEvent(id, ev)`, then call `commands.sendMessage(history, channel)`.
    - On `{ status: "error" }`, set `configError`, remove the placeholder, and set `streaming` to false.
  - **`applyEvent`:**
    - `delta` appends the text.
    - `done` marks the message `complete`.
    - An `error` of kind `cancelled` marks it `stopped`.
    - Any other `error` marks it `error` and stores the `ProviderError`.
    - Both `done` and `error` set `streaming` to false.
  - **`stop`:** calls `commands.stopReply()`.
